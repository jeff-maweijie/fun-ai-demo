
## 一、这是一个什么项目？

这是一个带有“持久化记忆”和“情绪感知”的极简版 AI 对话助理（Demo）。用的是deepseek 大模型，配置api-key到文件.env即可。
如果没有大模型api key的话，也可以直接运行文件，会走mock应答。

它的核心考察点不在于大模型本身的能力，而在于工程化实现对话状态管理。具体来说，实现了：

- **短期记忆（Context）**：滑动窗口式的多轮对话（保留最近6轮）。
- **长期记忆（User Profile）**：跨会话、跨程序重启的用户事实提取与存储（如：名字、喜好）。
- **情感计算（Sentiment）**：基于文本的粗粒度情绪分类，并让 AI 的回答适配该情绪。
- **数据隔离与容错**：多用户数据不串号，API 调用失败不能污染数据库。
  

## 二、所用技术栈（极简轻量）：

- **语言**：Python（最简单，生态最好）。
- **框架**：直接使用官方 SDK 即可（如 OpenAI 库或 DeepSeek 库）。
- **存储**：SQLite（标准库自带，无需额外安装）。
- **API 调用**：使用各大模型的 Function Calling / JSON Mode 功能（如 DeepSeek-V3, GPT-4o-mini）。


## 三、模拟输入user prompt 步骤：
| 步骤 | 用户操作或输入                                       | 需要看到的效果                                       |
|------|---------------------------------------------------|----------------------------------------------------|
| 1    | 用户A：“叫我小林吧，我喜欢喝拿铁。”                  | 保存称呼和喜好                                      |
| 2    | 用户A：“今天开会被批评了，有点难受。”                | 识别为低落或其他合理标签，回复能回应这件事           |
| 3    | 用户A：“你觉得我刚才说的那件事怎么办？”              | 能关联开会被批评，不需要用户重述                    |
| 4    | 重启程序，用户A新建会话：“你还记得我喜欢喝什么吗？” | 能使用持久化偏好回答拿铁；不要求记住所有旧会话内容   |
| 5    | 用户A：“我现在更喜欢喝茶了。”随后再次询问            | 偏好更新为茶，不继续说拿铁                          |
| 6    | 切换用户B：“你知道我喜欢喝什么吗？”                  | 不把用户A的偏好当成用户B的事实                      |
